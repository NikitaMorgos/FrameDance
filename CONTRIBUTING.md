# Как работать над проектом вдвоём (два разработчика, два Cursor)

## Репозиторий и доступ

- Код живёт в **GitHub**: [NikitaMorgos/FrameDance](https://github.com/NikitaMorgos/FrameDance).
- Второй разработчик: добавь его в репо как **Collaborator** (Settings → Collaborators → Add people) или через организацию.
- Каждый клонирует репо к себе и открывает в **Cursor**:
  ```bash
  git clone https://github.com/NikitaMorgos/FrameDance.git
  cd FrameDance
  npm install
  ```
- Файл **`.env`** в репо не хранится. Каждый создаёт свой из `.env.example` (для локального бота и сервера). Секреты для **Render** лежат только в Environment в панели Render — их меняет тот, у кого есть доступ.

## Git-процесс (чтобы не ломать друг друга)

1. **Ветка по задаче**  
   Не коммитить сразу в `main`. От своей копии `main` завести ветку, например:
   ```bash
   git checkout main
   git pull
   git checkout -b feature/название-фичи
   ```
   Или: `fix/баг`, `docs/readme` — как договоритесь.

2. **Коммиты и пуш**  
   Делаешь изменения, коммиты в свою ветку и пушишь:
   ```bash
   git add .
   git commit -m "краткое описание"
   git push -u origin feature/название-фичи
   ```

3. **Pull Request (PR)**  
   На GitHub: **Compare & pull request** из ветки в `main`. Второй разработчик смотрит код и нажимает **Merge** (или оба ревьюют — как решите). После мержа ветку можно удалить.

4. **Обновлять свой main**  
   Перед новой задачей подтянуть изменения:
   ```bash
   git checkout main
   git pull
   ```

Так вы не перезаписываете друг друга: работа в ветках, слияние через PR.

## Кто что делает

- **Задачи** можно вести в **GitHub Issues**: кто какую задачу взял, ссылки на PR.
- Крупные фичи лучше делить на части и делать отдельные ветки/PR.
- Деплой на **Render** делает тот, у кого доступ: мерж в `main` обычно запускает автодеплой. Секреты и переменные окружения меняются только в Render Dashboard.

## Cursor у каждого свой

- У каждого свой Cursor и своя копия репо (через `git clone`).
- Чтобы AI вела себя одинаково по стилю кода и правилам проекта, можно завести **правила в репо** (например, в `.cursor/rules/` или один файл в корне) и закоммитить их — тогда у обоих будут одни и те же подсказки для Cursor. Репозиторий уже с общими правилами можно не трогать, пока не понадобится.

## Краткий чеклист для второго человека

1. Получить доступ к репо на GitHub (Collaborator).
2. Клонировать репо, `npm install`, создать `.env` из `.env.example`.
3. Запускать локально: `npm run start:all` (или по отдельности `npm run bot` и `npm run server`).
4. Новую работу вести в ветке → пуш → создать PR в `main` → после ревью мержить.
5. Секреты и деплой: по договорённости (один владеет Render, второй только пушит в GitHub).

Если позже появятся тесты, линтер или CI — их можно описать в этом же файле или в README.
